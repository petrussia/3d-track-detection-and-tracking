# Как запустить Пеленг

Распакуйте весь ZIP и откройте папку `peleng-hackathon`. Это архив исходного проекта с весами YOLO11s, пятью видео и пятью CSV камер. Зависимости нужно установить отдельно; готового исполняемого приложения в архиве нет. Интернет нужен при первоначальной установке. Дальше обработка работает локально.

В `outputs/example-run/` лежит пример сохранённого прогона. Его `preview.jpg` и `report.html` можно открыть сразу, без установки Python. Фактические результаты и ограничения описаны в `docs/verification.md`.

## Windows

Установите 64-битный Python 3.12 с [python.org](https://www.python.org/downloads/). В установщике включите Python Launcher или добавление Python в PATH. `uv` для Windows не нужен.

В распакованной папке откройте терминал и выполните:

```powershell
.\setup.bat
.\run.bat --check-data
.\run.bat
```

Установка создаёт `.venv`, ставит версии из `requirements.txt` и проверяет SHA256 вложенных весов. При ошибке прочитайте сообщение в терминале и повторите `setup.bat` после её устранения. `run.bat` также запустит установку автоматически, если окружение ещё не подготовлено. Если в папке осталось окружение с другой машины, переименуйте `.venv` и выполните установку заново.

Без аргументов `run.bat` открывает сервер в режиме полного прохода на CPU (`--batch-ui --device cpu`). Откройте [127.0.0.1:8765](http://127.0.0.1:8765) и нажмите «Запустить». Окно терминала должно оставаться открытым. Для завершения сервера нажмите `Ctrl+C`.

Windows-запуск подготовлен, но на Windows в этой сборке не проверен. Подробности фактической проверки платформ указаны в `docs/verification.md`.

## macOS / Linux

Нужен [uv](https://docs.astral.sh/uv/). Откройте терминал в папке проекта:

```sh
chmod +x setup.sh run.sh
./setup.sh
./run.sh --check-data
./run.sh --batch-ui --device cpu
```

Затем откройте [127.0.0.1:8765](http://127.0.0.1:8765). Скрипт устанавливает окружение Python 3.12 и зависимости. Наличие пакетов зависит от ОС и архитектуры; при ошибке установки сохраните текст сообщения из терминала.

## Режим обработки и выбор точки объекта

Для первого запуска используйте `--batch-ui`: он обрабатывает все исходные кадры по порядку и показывает результат в браузере. На CPU запись может идти медленнее реального времени; дождитесь обновления кадров. Это полный проход без пропусков, а не обещание скорости 30 кадров в секунду.

При передаче своих флагов в `run.bat` указывайте режим явно, например `run.bat --batch-ui --device cpu --reference center`. Без `--batch-ui` или `--batch` программа повторяет запись в реальном темпе и может пропускать устаревшие кадры.

Для полного расчёта без браузера используйте `--batch`:

```powershell
# Windows
.\run.bat --batch --device cpu
```

```sh
# macOS / Linux
./run.sh --batch --device cpu
```

Алгоритм использует текущее изображение и оцениваемую 3D-форму грузовика. По умолчанию основные X/Y/Z относятся к передней грани (`--reference front`); `--reference center` выбирает геометрический центр объёма. Например:

```powershell
.\run.bat --batch-ui --device cpu --reference center
```

На macOS / Linux те же флаги передаются `./run.sh`. Обе точки экспортируются отдельно, когда их удалось определить. Это оценки по изображению, а не известная 3D-модель объекта. При слабых наблюдениях возможны допущения о поверхности, прогноз и потеря; смотрите состояния и методы в результате.

Новый прогон появится в `outputs/<время>/`: координаты в `trajectory.csv`, журнал в `observations.jsonl`, настройки в `config.json` и итог в `summary.json`. Координаты X/Y/Z записаны в сантиметрах, время в секундах. Пустые координаты означают потерю. Подробная инструкция находится в `README.md`.

Истинная траектория не входит во входные данные этого архива и не нужна для работы. Готовые отчёты могут содержать результаты отдельного сравнения с ней после прогона. Исходные видео являются тестовым набором задания; их копия не заменяет независимый проверочный набор организаторов.
