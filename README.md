# Пеленг: сопровождение грузовика по пяти камерам

Локальное решение по материалам SpaceHackathon: YOLO11s обнаруживает транспорт, текущие пиксели помогают продолжать сопровождение, а геометрическая модель объёма оценивает положение одного грузовика по видео и CSV камер. Есть браузерная демонстрация, причинный повтор записи в реальном темпе и последовательная обработка всех кадров. Истинную траекторию читает только отдельная команда оценки после прогона.

Требования из двух лекций и принятые допущения собраны в [docs/requirements.md](docs/requirements.md). Фактические проверки и результаты находятся в [docs/verification.md](docs/verification.md). Предоставленный архив является исходным тестовым набором. Отдельный проверочный набор по расписанию лекции ещё не выпущен; качество на нём и приёмка решения не подтверждены.

## Быстрый запуск

Начните с [START_HERE.md](START_HERE.md): там установка для Windows и macOS/Linux. Команды ниже выполняются из распакованной папки проекта. Если окружение уже подготовлено:

```sh
./run.sh --check-data
./run.sh --batch-ui --device cpu
```

Откройте [127.0.0.1:8765](http://127.0.0.1:8765), нажмите «Запустить». «Остановить» завершает прогон; «Запустить заново» сбрасывает сопровождение и создаёт новую папку. Прогрев модели проходит до запуска часов записи. Порядок показа: [docs/demo.md](docs/demo.md).

Для установки на macOS/Linux нужен Python 3.12 и [uv](https://docs.astral.sh/uv/):

```sh
./setup.sh
./run.sh --check-data
```

`requirements.txt` фиксирует версии зависимостей. Установка требует сети и подходящих пакетов для вашей ОС. После установки, при наличии весов `models/yolo11s.pt`, обработка работает локально. Сервер слушает `127.0.0.1`; видео не отправляются на внешний сервис.

В `data/` нужны пять пар файлов с номерами 1–5:

```text
Way1.FinalImage.CineCameraActor1.mp4
object_transform_CineCameraActor1.csv
… те же имена для камер 2, 3, 4, 5
```

`object_transform_SM_AA_track.csv` нужен только для последующей оценки. Он не требуется для запуска и проверки входов. `--check-data` проверяет открытие видео, размеры, число кадров, FPS и телеметрию камер без загрузки модели и истинной траектории. Синхронизация по кадру 0 остаётся допущением, а не измеренной поправкой часов.

## Режимы обработки

```sh
# Все кадры по порядку с показом в браузере, рекомендуется на CPU
./run.sh --batch-ui --device cpu

# Повтор по настенным часам без браузера
./run.sh --headless

# Каждый кадр по порядку, без ограничения темпом исходной записи
./run.sh --batch

# Другие входы и CPU
./run.sh --batch --data /path/to/data --device cpu
```

По умолчанию: веса `models/yolo11s.pt`, размер входа детектора 960, устройство `auto`, результаты `outputs/`. Доступны `--weights PATH`, `--imgsz 960`, `--device auto|cpu|mps`, `--outputs PATH`, `--port 8765`, `--reference front|center`. На Windows замените `./run.sh` на `.\run.bat`. Без аргументов `run.bat` выбирает `--batch-ui --device cpu`; с собственными аргументами режим указывайте явно.

В реальном темпе программа берёт только уже наступивший кадр, а при отставании пропускает устаревшие кадры. Один шаг обрабатывает пакет из пяти камер; пропуски считаются на одну камеру. Задержка включает декодирование, ML и подготовку изображения до публикации на сервере. Передача и отрисовка в браузере в неё не входят. Обработка всех 5×30 кадров в секунду не обещается.

`--batch` сохраняет каждый исходный индекс последовательно без браузера; `--batch-ui` делает тот же полный проход с браузером. Запись может идти медленнее реального времени. Скорость этих режимов не доказывает работу в исходном темпе. Во всех режимах нет будущих кадров, обратного сглаживания, дообучения нейросети на маршруте и кэша обнаружений из прошлых прогонов.

## Как устроено сопровождение

YOLO11s предлагает рамки транспорта. После нейросетевого захвата модуль `ImageEvidence` ищет текущие пиксели того же объекта: неподвижные камеры используют вычитание фона, а при чистом повороте фон переносится по текущей и прошлой позам камеры. Перемещение камеры сбрасывает такой фон. Проверки положения, масштаба, внешнего вида и полноты силуэта ограничивают ложные продолжения. Оптический поток не используется.

`detected` означает нейросетевое обнаружение, `tracked` — принятое наблюдение по текущему изображению (`foreground`), `coasting` — краткий прогноз без свежего наблюдения, `lost` — потерю. Наличие foreground не превращается в нейросетевую классификацию. Сопровождение не гарантирует идентичность среди нескольких похожих грузовиков.

Модель `ShapeEstimator` подбирает вертикальный прямоугольный объём по согласованным силуэтам нескольких камер. Его размеры оцениваются только по текущим и прошлым многокамерным наблюдениям; готовая 3D-модель не подставляется. Обрезанные силуэты не учат размеры, но после получения масштаба могут задавать ограниченные геометрические условия. Плохая геометрия и вырожденные объёмы отбрасываются. Вспомогательная геометрия лучей также проверяет, подходит ли рамка для оценки общего центра, а не только видимого фрагмента.

Когда масштаб уже определён, один ракурс может оценить дальность по известному размеру. Метод `cuboid_singleview` использует прошлые размеры и их ошибку; он не считается свежим стереоизмерением. `cuboid_multiview` использует несколько текущих ракурсов. Если подходящая форма недоступна, остаются проверенная триангуляция центров рамок, угловое обновление или явно обозначенное наземное допущение.

Отдельный фильтр центра корпуса оценивает движение независимо от выбранной выходной точки. Он помогает определить направление продольной оси, не принимая сдвиг передней точки при повороте за движение всего кузова. Направление «вперёд» выводится из причинно наблюдаемого движения при допущении, что машина едет передом; при неразрешённой неоднозначности передняя точка отсутствует.

`--reference front` (по умолчанию) выбирает центр передней грани оценённого объёма, `--reference center` — центр объёма. Передняя грань является приближением по изображению; точное положение pivot исходной 3D-модели неизвестно. До появления пригодной формы возможен контакт с предполагаемой поверхностью, в том числе ведущий нижний угол при устойчивом движении. Если передняя сторона ещё не определена, доступная оценка может относиться к центру. Всегда проверяйте `reference_point`; обе точки сохраняются отдельно, когда они доступны.

У мирового фильтра два режима:

- `assumed_ground`: текущее наблюдение пересекается с предполагаемой плоскостью `z=0`. После оценки размеров контакт может переводиться в центр/переднюю точку с учётом высоты объёма. Рельеф не измеряется. Случайный шум пикселей отделён от постоянной ошибки поверхности, которую повторные наблюдения не устраняют.
- `metric_3d`: обновления приходят от многокамерной геометрии, модели объёма или одиночного луча. Последний уточняет только положение поперёк луча и требует прошлой дальностной опоры. Её срок для углового сопровождения ограничен 5 секундами с последнего принятого дальностного обновления, включая оценку по ранее определённому размеру.

Без принятого наблюдения прогноз ограничен 0,5 секунды. Фильтр учитывает фактический шаг времени, неопределённость и допустимое движение. Смена режима, типа опорной точки или камеры наземного наблюдения начинает новый сегмент со сбросом скорости. Несколько согласованных полных многокамерных оценок объёма могут восстановить ошибочную привязку новым сегментом; одного удачного пересечения лучей для этого недостаточно.

Приняты сантиметры Unreal Engine, X вперёд, Y вправо, Z вверх, углы в градусах, идеальная камера без дисторсии и главная точка в центре изображения. Поворот камеры 5 берётся из телеметрии. Модели рельефа и готовой 3D-модели объекта в архиве нет. `uncertainty_m` включает заданные ошибки изображения/модели и сохраняемые систематические составляющие; это не откалиброванный доверительный интервал и не гарантия точности.

## Файлы результата

Текущий алгоритм сохраняет имя `causal_image_evidence_and_shared_shape_v2` в `config.json`. Каждый запуск создаёт `outputs/<UTC-время>/`:

| Файл | Содержимое |
| --- | --- |
| `config.json` | Режим, модель, размер входа, единицы и сроки действия прогноза |
| `observations.jsonl` | Исходный кадр/время, обнаружения, состояние камер и мирового фильтра, измерения и причины отклонения |
| `trajectory.csv` | Основные `Frame,Time_s,Loc_X,Loc_Y,Loc_Z`; состояние, метод, неопределённость, режим/сегмент, `reference_point`; отдельные `Center_X/Y/Z` и `Front_X/Y/Z` |
| `summary.json` | Время обработки, пропуски, задержка и число состояний |
| `preview.jpg`, `preview-*s.jpg` | Обзор пяти камер в конце и по ходу записи |

`Loc_X/Y/Z` записаны в сантиметрах, `Time_s` в секундах, `uncertainty_m` в метрах. При `lost` координаты пустые. `observed` означает принятое обновление фильтра; оно может быть только угловым. `metric_depth_observed=true` отмечает принятую текущую многокамерную глубину (`triangulated` или `cuboid_multiview`); у дальности по прошлому размеру этот флаг ложный. `coasting` означает прогноз. Режим и номер сегмента сохраняются в мировом состоянии журнала. Без ранее оценённого масштаба или другого допущения одиночный ракурс не определяет дальность и высоту.

## Оценка после завершения

Сначала сохраните прогон, затем укажите его папку:

```sh
.venv/bin/python -m peleng.evaluate \
  --run outputs/ИМЯ_ПАПКИ \
  --truth data/object_transform_SM_AA_track.csv

# Сравнение с ранее сохранённым прогоном на общих кадрах
.venv/bin/python -m peleng.evaluate \
  --run outputs/ИМЯ_ПАПКИ \
  --truth data/object_transform_SM_AA_track.csv \
  --baseline outputs/ПАПКА_БАЗОВОГО_ПРОГОНА
```

Команда добавляет `evaluation.json`, `errors.csv` и автономный `report.html` с графиками X/Y/Z, путём XY и ошибками. На Windows оценщик запускается через `.venv\Scripts\python.exe`. Он сопоставляет точные номера кадров, переводит сантиметры в метры, отдельно считает ошибки наблюдений и прогнозов, покрытие и пропуски. Сравнивается выбранная выходная точка; её геометрическое определение может отличаться от pivot истины. Наземные оценки входят в общие ошибки наравне с 3D-оценками; дополнительно ошибки приведены отдельно по режимам и методам. Подбора временного сдвига и интерполяции нет. Повреждённые строки истинной траектории исключаются и перечисляются в отчёте.

Доля шагов с обнаружением или координатой не равна recall детектора: разметки видимости и правильных рамок нет. Сравнивайте ошибки вместе с покрытием; при наличии базового прогона смотрите также общие кадры. Локальный отчёт по исходным видео не заменяет проверку на новом наборе.

## Проверка и упаковка

```sh
.venv/bin/python -m unittest discover -s tests -v
python3 scripts/package_delivery.py --run outputs/ИМЯ_ПАПКИ

# Включить видео и CSV камер для повторного запуска
python3 scripts/package_delivery.py \
  --run outputs/ИМЯ_ПАПКИ --include-inputs
```

Архив: `distribution/peleng-hackathon.zip`. В нём исходники, инструкции, фиксированные зависимости, YOLO11s и выбранный прогон в `outputs/example-run/`. `DELIVERY_MANIFEST.json` содержит размеры и SHA256 файлов. Можно добавить снимок демонстрации через `--screenshot /path/to/screenshot.png` и изменить выход через `--output PATH`.

Окружение `.venv`, Git и посторонние прогоны в ZIP не попадают. Без `--include-inputs` исходных видео нет. С этим флагом включаются только десять файлов камер; файл истинной траектории исключён всегда. Отчёт оценки и `errors.csv` могут содержать значения истины, уже использованные после прогона. Для новой независимой оценки исходную траекторию передают отдельно.
