# Исправление геометрии и повторного захвата

База сравнения: `23decea3ae146e2f2a08b2fcad66bf39870d5c51`.
Полные сравнения Way1 выполнены; итоговый кандидат v4 имеет смешанные результаты.
Актуальные цифры и ограничения приведены в [отчёте проверки](geometry-benchmark.md).

## Реализовано и опубликовано

1. WorldTrack больше не переносит состояние без проверки только из-за истечения
   сопровождения. Близкое метрическое измерение после короткого пропуска может
   пройти обычные innovation/motion gates без сброса скорости и сегмента.
   Смена режима/опорной точки, истечение глубины и несовместимая новая поза
   требуют подтверждения. Слабая однокамерная оценка не может принудительно
   переинициализировать трек. Добавлены predicted_position_cm, reset_reason,
   transition_reasons. Для перехода с предположения земли допускается серия
   согласованных независимых триангуляций; для переноса метрического состояния
   остаётся требование полной многокамерной формы.
2. ShapeEstimator проверяет гипотезы пар по всем пригодным полным силуэтам,
   выбирает согласованный набор и уточняет по нему. Ложная камера не обязана
   соглашаться со всеми остальными. В журнале появляется view_consensus с
   покамерными остатками. После обучения размера поддержка перепроверяется.
3. Выбор front больше не подставляет center при неизвестной передней стороне.
   Наземный контакт без известной высоты не экспортируется как центр/передняя
   точка. Внутреннее состояние тела может обучаться, пока front ещё не определён.
   predict_scene.py получил явный --reference center|front.
4. Размеры/ориентация/история ShapeEstimator откатываются после отклонённой
   геометрической гипотезы; время и номер уже обработанного кадра не откатываются.
5. Фильтр целевой точки не принимает производное измерение, если фильтр тела
   отверг исходную позу. Добавлена проверка перехода от предполагаемой земли
   к однокамерной форме: такой переход не должен преждевременно создавать front.

## Диагностический повтор scene2

`scripts/audit_reacquisition.py` повторяет только WorldTrack на сохранённых
raw_measurement. Базовая версия воспроизводит все 1932 сохранённых состояния
без расхождений. Это не полный повтор и не оценка ошибки по эталону.

| Показатель | База | Кандидат общего фильтра |
|---|---:|---:|
| Кадров с координатами | 1811 / 1932 | 1652 / 1932 |
| Покрытие | 93,74% | 85,51% |
| Наблюдение / прогноз / потеря | 1518 / 293 / 121 | 1376 / 276 / 280 |
| Скачки >10 м между соседними кадрами | 4 | 1 |

На 313 общих кадрах координаты изменились более чем на метр. Меньшее число
скачков частично достигнуто потерей покрытия. Это **не доказательство улучшения**.
Изменения ShapeEstimator и контракта reference этим повтором не проверяются.
Результат: `.codex-analysis/scene2-adapted/reacquisition_comparison.json` вне repo.

## Осмотр FBX

Файл организаторов имеет SHA256
`b8d08d3e62de67860698e5c84fd2344a5f0a9045e98509eff55043b6ec5a8391`.
С учётом трансформаций всех 8 mesh nodes и единицы 0,01 м:

- длина (ось Z FBX): 6,684864 м;
- ширина (ось X FBX): 1,677734 м;
- высота (ось Y FBX): 2,423812 м;
- центр объединённых границ: примерно (0; 1,190262; 0,022427) м;
- корневой origin не совпадает с центром объёма, у отдельных mesh свои origins.

`scripts/inspect_truck_asset.py` воспроизводит расчёт, сохраняет JSON и вершины
NPZ. Необязательная зависимость анализа: ufbx==0.0.5. Для инференса не нужна.
Матрицы geometry_to_world используются согласно
[документации ufbx](https://ufbx.github.io/elements/nodes/).

Сгенерированный Peleng-05-reverse/assets/scene.json содержит source_scale=3.28
и габариты 21,926354 × 5,502969 × 7,950103 м. Это не подтверждает actor scale
организаторских сцен. В сохранённых многокамерных измерениях scene2 медиана
габаритов 18,3997 × 8,89716 × 8,45638 м. Пропорции существенно отличаются
от FBX. Абсолютный размер по умолчанию не фиксируется. Добавлен отдельный режим
`--shape-dimensions-m L W H`; неопределённость размеров 10% сохраняется.

Дополнительная проверка `scripts/check_asset_projections.py` использовала только
размеченные train-кадры scene2, без val/test и без 3D-эталона. Полная оболочка FBX
подгонялась к 2D-рамкам с общей позой и масштабом. Семь кадров с normalized RMS
не выше 2,5 дали медианный масштаб 3,31414 и габариты 22,15456 × 5,56024 × 8,03285 м.
Результаты и монтажи лежат в `.codex-analysis/reference-point/asset-projections`.
Профиль `configs/truck-scene2-geometry.json` экспериментальный: основной фит
по-прежнему использует upright cuboid, а не точную оболочку FBX. Определение
переднего конца по движению пока сохраняет ограничение при заднем ходе.

Локальная проверка алгоритма: 173 tests + 16 subtests прошли. Полный запуск подготовлен
в `scripts/run_geometry_benchmark.py`: baseline/front, current/front,
current/front с заданными размерами на Way1; current/center без фиксации размеров на scene2.
Веса на Way1 одинаковы между вариантами. CSV эталона читается только после Engine.

## Проверка камер и времени

В обоих наборах для каждого видеокадра есть строка позы каждой камеры:
Way1 — 1001 кадр и 1002 строки на камеру; scene2 — 1932 кадра и 1933 строки.
Последняя дополнительная строка не используется для обработки видео. Пропусков
поз внутри видео нет. Поворот камеры меняется у №5 в Way1 и №2 в scene2.
CameraRig выбирает последнюю позу не позже текущего номера кадра; при полном CSV
это точная строка текущего кадра. Все видео 1920×1080, около 30 кадров/с.
Совпадение нулевого кадра разных камер остаётся предположением экспорта:
отдельной измеренной временной калибровки нет. Pinhole-модель не учитывает
дисторсию и предполагает центральную главную точку.

Первая итерация опубликована в ea252fff0f7d52fc91084ebb37dc1cdeb6b2d457,
финальный алгоритм v4 — в 8292b21c6b85c7308a526a62055b83d0427fc599.
Runner с основным режимом scene2 без фиксированных габаритов —
3c9f8699ec6599f1b4b4ad3f5db69d093ae6dc7c.

      допустимый масштаб и способ ограничения габаритов/ориентации без GT-подгонки.

      точный pivot импортированного организаторами actor пока не подтверждён.

- [x] Полный прогон scene2 с выбранными весами adaptation-v1 (conf=.5), сохранение
      траектории и диагностики. Для scene2 GT нет: точность в метрах не заявлять.
- [x] Сохранить воспроизводимые параметры/результаты и передать проверенный код
      в GitHub/Colab. Результаты доступны по ссылкам в итоговом отчёте.

Кандидат не принят как лучший: scene2 потеряла почти половину покрытия.
На 354 кадрах длинного пропуска фильтр тела принимал измерение, а фильтр центра
продолжал ждать повторного захвата. Следующая итерация должна объединить состояние
тела и производной точки, затем заново пройти полную проверку. Дальнейшие
ключевые точки и точная mesh-поза в этой итерации не реализованы.
