# Демонстрация и передача

Команды выполняются из распакованной папки проекта. Для установки и Windows-запуска начните с [START_HERE.md](../START_HERE.md). Перед показом откройте [verification.md](verification.md): там фактические результаты и ограничения последнего проверенного прогона. Предоставленные видео являются исходным тестовым набором. Отдельный проверочный набор организаторов по расписанию лекции ещё не выпущен; копия исходного набора не заменяет его.

## Подготовка

```sh
./run.sh --check-data
./run.sh --batch-ui --device cpu
```

На другой машине выполните установку по START_HERE. Веса лежат в `models/yolo11s.pt`; видео и CSV камер находятся в `data/`, если архив собран с `--include-inputs`. Windows: `.\run.bat --check-data`, затем `.\run.bat --batch-ui --device cpu`. Полный проход может идти медленнее исходной записи, зато не пропускает кадры.

Откройте [127.0.0.1:8765](http://127.0.0.1:8765). Показывайте только локальную страницу.

## Сценарий показа

1. Нажмите «Запустить» и дождитесь прогрева. Покажите пять ракурсов одного грузовика. Поворот камеры 5 берётся из CSV камер.
2. Покажите состояния рамок: нейросетевое `detected`, текущее изображение `tracked`, прогноз `coasting` и потерю `lost`. Foreground продолжает нейросетевой захват по свежим пикселям, но не является новым результатом классификатора. При перекрытии координаты не продолжаются бесконечно.
3. Покажите мировые X/Y/Z и метод. `cuboid_multiview` оценивает объём из нескольких текущих ракурсов. `cuboid_singleview` оценивает дальность по ранее определённому размеру; свежей стереоглубины в нём нет. Наземный режим явно использует условную поверхность. Неопределённость зависит от модели и не откалибрована на независимых данных.
4. Покажите тип точки. По умолчанию выбран центр передней грани (`--reference front`), а `--reference center` выбирает центр объёма. Это приближения по изображению с неизвестным отношением к pivot модели. До определения формы/направления возможна другая опорная точка: её имя записано в `reference_point`. В CSV отдельно сохранены доступные координаты центра и передней грани.
5. Покажите режим запуска. В `--batch-ui` кадры идут по порядку, показатель времени относится к одному пакету пяти камер. В реальном темпе показывается отставание, а старые кадры могут пропускаться. Числа скорости полного прохода не являются обещанием работы 5×30 кадров в секунду.
6. Нажмите «Остановить», затем «Запустить заново». Покажите сброс состояния и новую папку результатов. Для итоговых чисел используйте завершённый прогон из `verification.md`, а не короткий запуск для проверки кнопок.
7. Откройте сохранённый `report.html`. Сравните X/Y/Z с истиной, ошибки наблюдений и прогнозов, затем покрытие и разбивку по методам. Наземные оценки входят в общие ошибки. Истина прочитана отдельным оценщиком после обработки; качество переноса на новый набор этим не доказано.

Если требуется пояснить восстановление, покажите журнал сегментов: смена режима/опорной точки начинает новый сегмент со сбросом скорости. Повторный захват ошибочной 3D-привязки требует согласованных полных многокамерных оценок объёма. Отдельный фильтр центра корпуса помогает оценивать направление, не принимая вращение передней точки за перемещение кузова.

Для полного экспорта без браузера используйте `./run.sh --batch` или `.\run.bat --batch --device cpu`. Если расчёт ещё идёт, можно открыть сохранённый пример из `verification.md` и прямо сказать, что показываете готовый результат.

## Передача архива

Выберите завершённую папку с `config.json`, `observations.jsonl`, `trajectory.csv` и `summary.json`. Если нужны графики качества, сначала запустите оценщик из README. Затем:

```sh
python3 scripts/package_delivery.py \
  --run outputs/ИМЯ_ПАПКИ \
  --include-inputs
```

Архив появится в `distribution/peleng-hackathon.zip`; выбранный прогон внутри называется `outputs/example-run/`. Для добавления снимка интерфейса передайте `--screenshot /path/to/screenshot.png`. Флаг `--include-inputs` включает только пять видео и пять CSV камер. Истинная траектория в исходных данных в ZIP не включается. Уже построенные отчёты и таблицы ошибок содержат результаты сравнения с ней.

Для повторного запуска после распаковки:

```sh
./setup.sh
./run.sh --check-data
./run.sh --batch-ui --device cpu
```

`DELIVERY_MANIFEST.json` хранит SHA256 каждого вложенного файла, кроме самого манифеста. Архив не содержит виртуального окружения: зависимости устанавливаются из `requirements.txt`. Повторная оценка требует отдельного файла истины. Перед отправкой организаторам нужно проверить их итоговую схему и форму сдачи.
